Boot an operating system from a blockchain.

chainboot stores whole Linux systems on the Solana ledger and runs them on your own computer, in your own terminal, at native speed. There is no server in between: it reads the chain through the RPC endpoints you give it and checks every byte.

# how it works

  
A ledger is a hard disk, if you cut the files small enough.

  

    

      
1
Files become transactions
A Solana transaction can carry 3,912 bytes of free data for a fixed fee of 0.000005 SOL. chainboot cuts a file into pieces and puts each piece into a transaction.

      
2
One signature is the address
Lists of signatures are stored the same way, forming a small tree. The signature of the top transaction is all you need to find a file of any size, with its size and SHA-256.

      
3
Whole blocks, not single requests
One request returns a whole block with hundreds of the file's transactions. That is why a single free endpoint downloads Ubuntu in about a second.

      
4
Verified, then run natively
Signatures and hashes are checked before anything is used. The system is unpacked once and runs directly on your processor: no emulation.

    

    
              head              the file's address
            /  |  \             size + SHA-256
      branch branch branch      61 signatures each
      / | \     ...
   leaf leaf leaf               3,912 bytes each

# what you get

  
Small program, strong guarantees.

  

    
[v] Verified
RPC endpoints only deliver bytes. A wrong or dishonest endpoint can be slow, but it cannot change what you run.

    
[>] Fast
Programs run on your own processor. Work is spread over all your endpoints, with batching, hedging and learned rate limits.

    
[*] Yours
Your machines are saved to chain, encrypted with a key that only your wallet can make. No account, no company.

    
[#] Private by default
What you publish is encrypted for your wallet alone. Sharing with everyone takes an explicit --public.

    
[+] Universal
Ubuntu is the example, not the limit. Any Linux distribution, on amd64 or arm64, can be published by anyone.

    
[/] A toolkit
Built on a TypeScript SDK with no dependencies: files on chain, pointers, an RPC pool, wallet-derived encryption.

# continue anywhere

  
Your machine follows your wallet.

  

    

      
Sign one message with your wallet. From it chainboot derives an encryption key and a small helper account that pays the fees, so the wallet is never asked again. Everything you change is saved after each session, encrypted. On another computer: sign in, type the same command.

      
    
        
  • Only what is new is uploaded. A session that installs a few packages costs well under 0.001 SOL.
    • 
        
  • Every save is kept. Go back to any earlier one.
    • 
        
  • Two computers changed the same machine? chainboot tells you and never picks silently.
    • 
        
  • Works with Phantom, Solflare, Backpack and any Wallet Standard wallet, or a keypair file.
    •

# publish your own

  
Build a machine. Put it on chain.

  

    

      
publish


# set up a machine the way you like it
$ chainboot run solinux-minimal --name mybox
$ chainboot export mybox mybox.tar

# for yourself (the default): encrypted
$ chainboot publish mybox.tar --name mybox \
    --version 1.0 --reuse solinux-minimal
$ chainboot run me/mybox

# for everyone: say so
$ chainboot publish mybox.tar --name mybox \
    --version 1.0 --public --keypair me.json

    

    

      
A root file system of any distribution works: a download from the distribution, a debootstrap, a docker export, or a machine you configured by hand.

      
    
        
  • Private by default. A ledger never forgets, so the safe choice is the default. Only your wallet can list, fetch or read what you publish.
    • 
        
  • Pay only for what is new. Files that are already on chain, like the Ubuntu base, are referenced, not uploaded again.
    • 
        
  • Reproducible. An image's digest depends only on its files. Anyone can rebuild and compare.
    • 
        
  • No program to deploy. Everything uses ordinary transactions and the existing Noop program.
    • 
      

    

  






  
# the sdk

  
Four building blocks. No dependencies.

  

    

      
    
        
  • ChainStorefiles of any size on the ledger, addressed by one signature, verified on read
    • 
        
  • putPointer / getPointernames that only their owner can move
    • 
        
  • RpcPoolmany endpoints that behave like one fast, reliable one
    • 
        
  • deriveVault / seal / openencrypted private state unlocked by a wallet signature
    • 
      

      
Package registries that cannot be changed quietly. Development environments shared with one line. Game saves owned by the player. Websites whose every file is on chain. The docs have a page of ideas.

    

    

      
store.mjs


import { RpcPool, ChainStore, Keypair } from "chainboot";

const store = new ChainStore(new RpcPool([url]));
const me = Keypair.fromFile("me.json");

// write: any size, resumable
const ref = await store.put(me, data);

// read: verified against its SHA-256
const back = await store.get(ref);

One line. No administrator rights.

  

    

      
      
      
    

    
$curl -fsSL https://raw.githubusercontent.com/bettercallfolio/chainboot/main/install.sh | sh

Linux runs machines directly. Windows uses WSL 2. macOS uses OrbStack, Docker Desktop, Podman or Lima. The installer checks every download against its SHA-256.

Early, working, and clear about its limits.

  

    

      
works today

      
    
        
  • Publish, list, download and verify images
    • 
        
  • Run machines on Linux, amd64 and arm64
    • 
        
  • Encrypted saves, restore, history, automatic saving
    • 
        
  • Private images for one wallet
    • 
        
  • Web interface and wallet sign-in
    • 
        
  • Tested end to end on Solana devnet
    • 
      

    

    

      
good to know

      
    
        
  • A machine is not a security sandbox: run images you trust
    • 
        
  • It uses your kernel and does not boot systemd
    • 
        
  • Ledger data cannot be erased; saves are encrypted but stay
    • 
        
  • Windows and macOS engines are new and little tested
    • 
        
  • No official images on mainnet yet
    • 
        
  • Devnet is a test network and can be reset
    •
